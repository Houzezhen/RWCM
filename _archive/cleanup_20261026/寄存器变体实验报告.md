## 前置调研：相关工作中的寄存 token 与块注意力

本实验的两个核心组件——寄存 token 与块因果注意力——均来自近期代表性工作，先梳理它们的用法，再说明本实验与它们的差异。

### 调研 1：VGGT 的寄存 token（CVPR 2025 Best Paper）

VGGT（Visual Geometry Grounded Transformer，多视角 3D 几何前馈重建）在每张输入图的 DINOv2 patch token 后拼接 **1 个相机 token + 4 个寄存 token**（寄存用法引 Darcet et al. 2023）：

```
每张图 i: (图像 token t_I^i, 相机 token t_g^i, 寄存 token t_R^i)
  → 交替注意力（帧内层 + 全局层交替堆叠 24 层）
  → 相机 token → 相机头；patch token → DPT 头（深度/点云）；寄存 token → 丢弃
```

要点：
1. **寄存是"每视角独立"**：每张图各带 4 个寄存（参数共享、逐图复制），只吸收注意力伪影，不进任何输出头——与本实验的空间组（D2，ViT 内逐帧同款用法）机制同源同构；
2. **存在带读出头的特化 token**：相机 token 单独喂相机头，有明确梯度信号——本实验的寄存均无专门读出头（梯度全靠 state token 间接回传），这是一个可借鉴的差异点；
3. **交替注意力 ≈ 块注意力家族**：帧内（块内）+ 全局层交替，但全局层无因果（几何重建视角对称合理）——本实验的 value 任务必须因果，这是任务本质决定的分岔。

### 调研 2：LeVJEPA 的块因果注意力与稀疏 token（Balestriero/LeCun 系）

LeVJEPA（视频版 LeJEPA，SIGReg 防塌缩）与 WCM 的关系有两层：

**a) 损失函数同源**：WCM 训练配置直接借用 LeJEPA 的 SIGReg 正则（`sigreg_weight=0.01, knots=17, num_projections=1024`，与官方默认一致）——将 latent 推向各向同性高斯，小 batch 微调下防塌缩。

**b) 块因果注意力**：LeVJEPA 证明编码器可用块因果注意力训练且"无精度代价"，使每帧表示只依赖过去。但关键前提是**其块=单帧**：

| | LeVJEPA | 本实验块融合版 |
|---|---|---|
| 块的构成 | 单帧内全部 patch（不跨时间戳） | 2 帧一组（跨时间戳） |
| 块内双向 | 帧内 patch 互看——**无任何未来** | 帧 0↔帧 1 state 直连——**含 1 帧确定性未来** |
| 任务目标 | 自监督不变性（不依赖未来） | value=未来回报的函数（对泄漏极敏感） |
| 结论 | 块因果"免费" | 本实验证明：跨时间戳的块内双向=确定性泄漏，"免费"不成立 |

**c) 稀疏 token 辨析**：LeVJEPA 的 95% token dropping 是**输入端稀疏化**（丢 patch 省算力，不破坏因果）；本实验的 5% 未来泄漏是**因果图上随机加边**（BigBird 式随机注意力，主动破坏因果换取前瞻信息）——两者名字相近、机制相反，且本实验的泄漏消融（§4.1）证明后者对 value 指标虚增显著。

### 调研小结：本实验的定位

- 空间组（D2）= Darcet/VGGT 同款寄存的直接应用（作为标准基线，非自创弱基线）；
- 块融合版 = "寄存搬到 latent 层" + "LeVJEPA 式块因果但块跨时间戳"的组合变体；
- 本实验的增量贡献：(1) 寄存 token 在 value 模型上的变体系统消融（VGGT/LeVJEPA 均未涉及）；(2) 块粒度作为"泄漏深度旋钮"的发现与量化（LeVJEPA 的无代价结论不适用于预测未来型任务）。

## 摘要（一页看懂）

**问题**：空间寄存器（Darcet 2023，ViT 内 4 个 token）已证明能提升价值模型精度（D2，mse -21%）。本报告在空间寄存器之外探索寄存 token 的**其他变体**——不同的放置位置（ViT 内 / latent 层）、注意力拓扑（前缀读出 / 块内双向+块间因果）、组合方式（两处独立注入 / 同层融合）——试图找到比空间寄存器更好的配置，并检验各变体在 OOD（环境小改）下的泛化。

**实验的变体**：
| 变体 | 结构 | 一句话 |
|---|---|---|
| 前缀读出版 | 4 个寄存，逐帧前缀因果读出注回 | latent 层、跨帧聚合 |
| 双处注入版 | ViT 内 4 寄存 + latent 层 4 寄存，独立注入 | 失败：互相干扰 |
| 块融合版 | 8 个寄存 + 时间块注意力（块内双向/块间因果），单层融合 | 修正版组合 |
| 单块版 | 同上但块=单帧（严格因果，无块内未来可见） | 最终消融对照 |

**核心结论**：
1. 严格因果下的诚实排名：**单块版 ≈ D2 ≈ 无泄漏块融合版**（mse 0.0087~0.0095）> 前缀读出版（0.0103）> 基线（0.0117）≈ 双处注入版（0.0118）——**没有任何变体显著超越空间寄存器**；
2. 块融合版训练时的 SOTA（0.0080）**主要来自 5% 未来泄漏**——真机部署不存在此优势；
3. 寄存收益与放置位置（ViT 内/latent 层）、注意力拓扑（块 mask）基本无关，主要来自"额外可学习容量/正则效应"；
4. OOD 泛化假设未获支持：纯结构下各版本 Pearson 均为弱正（+0.04~+0.07，不可用量级）；块内未来可见性（块大小=2）反使 OOD 校准显著变差（mse 0.098 vs 0.059）；
5. **方法论警示**：value 类指标对微小因果破缺极敏感——5% 随机放行或 1 帧块内双向均会虚增同分布精度与 OOD Pearson，时序结构改动应默认做泄漏消融。

## 1. 动机与假设

空间寄存器（Darcet 2023）解决**单帧内** CLS→patch 注意力伪影；价值预测是时序任务，窗口内存在另一类冗余：**跨时间步不变的信息**（环境布局、任务指令相关背景、相机位姿）。当前 trunk 里这些信息被逐帧重复编码，占据 state token 容量。

**假设**：维护一组跨时间步共享的寄存 token，专门从多帧 token 中吸收时序不变信息，再注回各时间步，可以：
1. 让 trunk 注意力更聚焦于帧间变化（任务进度）；
2. 改善 value 预测，尤其在 OOD（环境小改但布局恒定）场景。

## 2. 方法（按变体演进）

### 2.1 前缀读出版（`TemporalRegisterBlock`，因果版）

```
state_tokens [B,T,D]（语言融合之后）
    ├─ query: 同一组 4 个共享寄存复制到每个时间步 -> [B, T*4, D]
    ├─ 读出: 行 (t,k) 只能看前缀 key 0..t（因果 attn_mask）+ 无效步屏蔽
    ├─ 写回: 每帧 t 的 4 个读出 → 线性池化为单一注入向量 [B,T,D]
    └─ 残差注回：state_tokens + injection（逐帧各自的前缀摘要）
```

- 位置：语言融合之后、trunk 之前（latent 空间，与 ViT 内部解耦）；
- **因果约束**：第 t 帧只吸收帧 0..t 的前缀信息——对齐部署逐帧可见性；
- 寄存参数 `[1, 4, D]` 跨时间步共享；输出丢弃寄存本体。

### 2.2 双处注入版（两处独立注入——失败设计）

ViT 内 4 个空间寄存（D2 同款）+ trunk 前 2.1 节的前缀读出块同时开启、各自注入。

### 2.3 块融合版（`BlockRegisterFusion`，组合的修正设计）

针对双处注入失败的重新设计：把全部寄存放进**同一个块注意力层**直接交互。

```
每时间步 token 组: [state s_t ｜ 4 个寄存A ｜ 4 个寄存B]（寄存参数跨步共享）
时间块: block_size 帧/块（默认 2），帧 0..1 = 块 0，帧 2..3 = 块 1

mask（True=屏蔽）:
  块内: 同块 token 双向互见（含两类寄存互看）
  块间: 只能看 ≤ 自己块的时间（块级因果）
  稀疏未来泄漏（可选）: 被屏蔽的未来 token 随机放行 5%
输出:  丢弃全部寄存 token，state token 残差注回
```

与失败双处注入版的三点关键区别：
1. **同层融合**：全部寄存在同一 attention 里直接交互（双处注入版隔层不可见、各自为战）；
2. **寄存统一移到 latent 层**：ViT 内寄存关闭，干扰源头减半；
3. **10×lr 只命中寄存本体**（参数名 `*registers`），attention 投影留主组 1×（修正双处注入版振荡根源）。

### 2.4 单块版（block_size=1，严格因果消融）

块=单帧：块内双向退化为帧内（state+寄存），块间严格因果。数值验证显示融合层帧间信息流 ≈0（改历史帧，后续帧输出变化 ~1e-7）——此版本实际是"每帧内 8 个静态可学习锚点 + 残差注入"，近似 latent 层放置的 D2。

**值得注意的收敛**：单块版的块划分（块=单帧、块内不跨时间戳）恰与 LeVJEPA 的块因果配置一致——本实验经过前缀读出、双处注入、跨时间戳块融合（bs=2）的探索后，最终胜出结构收敛回"块不跨时间戳"这一配置。这与调研节的论断互相印证：块内跨时间戳的双向交互在 value 任务上不是收益来源（其收益是泄漏假象），跨时间戳的时序融合仍由 trunk 的因果注意力承担。

### 2.5 结构再认识（重要修正）

1. **块融合版的 8 个寄存无角色之分**：两类寄存参数化、可见性 mask 完全对称，命名分工只是初始化期望；state token 本身在块 mask 下跨帧可见，寄存并无独占时序通路。块融合版准确描述应为"**寄存增强的块因果注意力层**"（≈ 搬到 latent 层的 Darcet 寄存 + 时间块 mask）；
2. **块内双向 = 确定性泄漏**：块大小=2 时帧 0↔帧 1 state 直连，每窗口必发生深度 1 帧的未来可见。无泄漏消融版只消除随机 5% 泄漏，未消除该确定性泄漏——单块版才是严格因果对照；
3. 设计谱系：块因果 mask 参考 LeVJEPA（块=单帧、帧内双向、无精度代价——但其目标是自监督不变性，不依赖未来；value 任务目标是未来回报的函数，"免费"性质不成立）；5% 随机放行更接近 BigBird 随机注意力（因果图上随机加边），与 LeVJEPA 的输入端 95% token dropping（不破坏因果）机制相反。

### 2.6 训练配置

- 寄存参数（`*registers`）单独 10×lr（冷启动经验，D2 验证有效）；attention 投影留主组 1×；
- 其余（seed=3072、数据 0814、损失 value1+next1+sigreg0.01、warmup300）与 C2/D2 完全对齐；
- 历轮 best 均出现在 ep1-8、后期过拟合回升 → 消融版统一 10ep 定版。

### 6.4 机制证据：训练后 top5 注意力分析（2026-09-08）

**目的**：价值指标无差异（§6.2）不代表结构无作用——直接抓真实训练后 checkpoint 的 ViT 最后一层 CLS→patch 注意力，检验寄存是否真的吸收了注意力伪影。与价值指标形成"机制 × 指标"二维对照。

**方法与修复**：脚本 `scripts/ablation_register_tokens_trained.py`。实现是"双程"结构（[model.py:122-130](file:///home/user/code_1/WCM/world_critic/model.py#L122-L130)）：第一程 backbone 正常前向（197 token 无寄存）→ 拼接 K 寄存后再把 12 层重跑一遍（201 token，寄存只在此程参与注意力）→ 输出取第二程 CLS。hook 必须抓**第二程**。调试中发现关键 bug：脚本构建模型时漏了 `model_cfg.vision = vc`，导致模型用了默认 K=0 配置、寄存为 None、第二程不执行——修复前所有 K>0 模型的 top5 实为第一程（无寄存）数据，等同 baseline，全部作废。修复后 K>0 模型正常加载寄存并测第二程。

**结果**（5cut 数据 3 batch × 4 × 4×2 帧 = 72 样本，CLS→patch 权重 top5 占比）：

| 模型 | ViT 内寄存 | top5_ratio | entropy | 说明 |
|---|---|---|---|---|
| baseline | 无 | **0.992** | 1.60 | 注意力严重塌缩（99% 给前 5% patch） |
| reg4_d2（s3072） | K=4 | **0.287** | 0.86 | 训练后寄存把 top5 拉到最低 |
| reg4_d2_s42 | K=4 | 0.626 | 1.27 | |
| reg4_d2_s1337 | K=4 | 0.704 | 1.07 | |
| bs1_s3072（单块版） | **0**（寄存仅在 trunk） | 0.9999 | 1.28 | 与 baseline 同量级——符合结构预期 |

**解读**：

1. **寄存真实、持久地吸收了注意力伪影**：D2 三 seed 训练后 top5 全部大幅低于 baseline（0.29~0.70，均值 ≈0.54 ± 0.21），且强于训练前随机寄存的静态吸收（前置报告 §5.2：K=8 ≈0.887）——10×lr 让寄存真正"学会"吸收；seed 间有散布但方向完全一致；
2. **单块版不在 ViT 内**：bs1 的 8 寄存属 `BlockRegisterFusion`（latent/trunk 层），故 ViT 注意力与 baseline 无差（0.9999）——印证其机制路线是"trunk 层融合"，两条路线机制彻底分开；
3. **机制与价值指标脱钩（核心发现）**：寄存把 top5 从 0.99 拉到 0.54（机制层面天翻地覆），但 value mse/Pearson 无显著差异（§6.1）——**注意力伪影的修复在这个任务上不转化为价值收益**，为 §7.5"时间捷径稀释视觉学习"假说提供了独立证据：模型不靠视觉学（数帧即可），改不改视觉注意力都无所谓；
4. **度量注意点**：top5 取的是完整 softmax（201 token）中给 patch 的原始权重和（未对 patch 子集重归一），D2 数值偏低部分来自寄存分走权重——但正是"寄存分走权重"这个行为本身构成了吸收的证据，方向性结论不受影响。

**对论文的意义**：这是"寄存机制有效但任务不需要它"的直接证据——如果"帧号计数"捷径诊断（§7.5 方案）坐实，论文可写：**在时间主导的直线 return 任务上，寄存成功修复了注意力伪影（机制层），但该修复不产生价值预测增益（任务层），因为模型未在利用视觉表征**——机制实现正确性与任务适用性分离开，是一个干净且可辩护的双层结论。

### 7.5 return 标注的本质：直线是定义的必然（机制层重要澄清）

**return 公式溯源**：本项目即 WCM 官方仓库（论文 arXiv:2607.29613），但其 RL/return 生成代码未开源；仓库数据管线实际采用 **π\*0.6（RECAP，arXiv:2511.14759）Eq.5** 公式（代码注释明示，`scripts/add_returns_to_lerobot.py:695`）：中间步 reward=-1、成功终点 0、失败终点 -C_fail、γ=1 → **成功集 return = -剩余步数/task_max，数学上必然线性**；失败集为 -1 平线（+末段）。数据验证：成功集每帧固定 +0.0029 递增；失败集全程 -1。与 π0.6 原版唯一差异是归一化分母（task_max vs task_max+c_fail），仅标尺差 2 倍，排序不变。详见 8 月调研文档 `pistar06_vs_wcm.md`。

**为什么 WCM 原论文的 value 不是直线**：原论文在 **RL 在线 rollout** 中使用 value——return 随策略/动作分支实时变化，模型必须看图；我们是**离线固定轨迹上预写死的标注**，此时"剩余步数"与画面内容几乎冗余（任务时长规律：剪辑后 100~229 帧）。

**捷径假说（解释力覆盖全报告三大谜题）**：模型可能学到"帧号计数 → return"而非"看图判进度"。可统一解释：
1. 同分布 Pearson 高达 +0.93（数帧即可拟合直线）；
2. OOD Pearson 天花板 ≈+0.05（换环境后帧号-进度映射漂移，看图能力从未被逼出来）；
3. 各结构变体（含 register）无显著差异（都在数帧，视觉容量冗余）。

**验证方案（纯评估，无训练）**：① 按窗口内绝对帧号分桶画误差曲线（若误差集中出现在时长-进度映射异常的分桶，则坐实计数）；② 打乱帧序/时间重采样后对比预测漂移；③ 若坐实，后续用"区分成败 AUC + 终点前 N 帧提前识别率"替代直线 mse 作为主指标。

## 8. 修正后的最终结论（截至 2026-09-08 晚，扩训判定已补，见 §8.2）

1. ~~变体未超越空间寄存器~~ → **各寄存变体之间无显著差异**（三 seed 均值全部互相落在 ±1 std 内）；单 seed 时代"D2 最优 / 单块版最优"均为 early-stop 侥幸；
2. **寄存 vs 无寄存**：方向上寄存组普遍略优于 baseline（旧 val 与 5cut 一致），但幅度（3~7%）与 seed 散布同量级，**尚不能宣称显著**——扩训组已判定：无稳定增益（§8.2，且 D2 线还叠加 §8.3 的实现混淆）；
3. **评估方法论（本报告最扎实的贡献）**：724 窗口 val + 单 seed + early-stop best 的组合会稳定制造虚假 SOTA（本案例：把 3% 的真实差异夸大为 26%）；value 模型实验必须：多 seed、万级窗口独立测试集、报告均值±std；
4. **未来泄漏虚增指标**（0% vs 5% 两点已确认）：5% 随机放行使同分布 mse 虚降、在诚实测试集上优势消失；块大小=2 的确定性泄漏恶化 OOD 校准——LeVJEPA"块因果无代价"结论不适用于 value 任务；
5. **外部效度限制**：单任务（toiletButton）、全成功测试集（无法测成功/失败区分能力）、单一环境——所有结论待扩训 + 多任务验证；
6. **机制层：寄存真实生效但被任务层稀释（§6.4 已坐实机制）**：训练后 D2 三 seed top5 0.29~0.70（baseline 0.99），寄存确实吸收了注意力伪影；但该机制修复不转化为 value 增益——与 §7.5"帧号计数"捷径假说互相印证（任务不逼视觉学习，改注意力无收益）；
7. **机制实现正确性说明（§6.4 记录）**：曾误测到"寄存死参数/std 不动"假象——真因是注意力分析脚本漏赋 `model_cfg.vision`（用默认 K=0 构建），扰动测试证实寄存完全接入计算图（扰动 ×10 输出变化 5e-2 vs 对照 6e-3）。此坑提示：**任何"XX 无作用"结论前须先验证组件确实参与了计算**。

### 8.3 代码审查：D2 寄存实现的架构问题（2026-09-08 晚，用户质疑触发）

**触发与排查证据链**（用户质疑"扩训验证曲线波动大，寄存训练代码肯定有问题"）：
- **训练 loss 全程平滑**：三模型 36k 步每 500 步均值单调降（0.13→0.015），相邻段 |Δ| 中位 0.0004，无尖峰无发散；梯度裁剪（train.py:392-397）正常 → **训练本身无 bug**；
- **验证锯齿来自小验证集**：177 集 ×0.1 ≈ 18 集，单轮波动 ±0.005；且 **baseline 抖得最凶**（s3072 极差 0.0129 > bs1 0.0098 > reg4 0.0073），非寄存器特有；旧 30ep reg4_r2 历史上抖得更剧烈（0.009↔0.018）→ 锯齿不是扩训/寄存新引入；
- 但深挖实现发现真正的架构问题（下 P0）。

**P0（架构级，最重要）：reg4 ≠ "baseline + 4 寄存器"，而是"ViT 完整跑两遍"**
- 实现（model.py:117-130）：先完整 forward 12 层 ViT → 把寄存器拼到 last_hidden_state 末尾 → **再过全部 12 层** → 取 CLS 投影；
- 后果①：CLS/patch token 实际过 24 层（baseline 只 12 层），**深度与算力 ×2**——D2 vs baseline 的任何差异都混杂"容量翻倍"因素，寄存器本身的效果被污染（可解释 §5/§8.2 中 seed 间结论反复翻转）；
- 后果②：第二遍循环**没过 ViT 最终 LayerNorm**（HF forward 末尾有，手写循环没有）→ D2 的 CLS 读出是未归一化残差流，projection 需重新适应尺度；
- 后果③：寄存器语义偏离标准做法（Darcet et al. 2023《Vision Transformers Need Registers》）：寄存器应在**第 0 层输入**就进入序列、随全部层一遍流动；现实现只能接触"已编码完毕"的特征，吸收的信息天然受限；
- **bs1 的 `BlockRegisterFusion` 是干净的**（trunk 深度不变、寄存只做残差注入）——被污染的只有 D2 线；这也意味着 §8.1"bs1 在 OOD 上突出"的结构归因不受本问题影响。

**P1（选点不稳）**：best.pt 按单轮验证 mse 选（train.py:435-445），在 18 集锯齿上等于**抓噪声谷底**——"训练波动大"观感的直接来源。标准解法：训练维护 EMA 权重（decay≈0.999），按 EMA 验证 mse 选 best。

**P2/P3（小项）**：`min_lr_ratio: 0.1`（10ep 结束 lr 仍有峰值 10%，验证曲线尾部漂着不收）；bs1 泄漏 mask 固定 seed=0（每 forward 同一张随机 mask，当前 leak=0 实验不受影响）；`register_lr_scale: 10` 修复 P0 后应复查（寄存从第 0 层参与，或只需 3~5）。

**修复方案（P0 已实施，2026-09-08 深夜；改动全部加开关、默认保持旧行为）**：
- P0 ✅：`vision.register_insert: early|late`（默认 late=旧行为）。early = `backbone.embeddings(...)` 取第 0 层输入 → 拼寄存器 → 12 层一遍 → `backbone.layernorm` → 取 CLS（model.py early 分支）。**已验证**：① late 路径改动前后输出逐位一致（固定 seed 回归测试）；② early 路径形状/有限性/寄存器梯度存活（grad L2 1.8e+2 vs late 1.5e+2）；③ 旧 checkpoint（wcm_reg4_r2）经评估脚本真实路径（`config_from_checkpoint_payload`→`build_model`→`load_state_dict` strict）重载成功且默认落 late；
- P1（EMA 选 best）：**未实施**，复查 run 先不加（避免双变量混淆，且 baseline/reg4-late 对照组都没有 EMA）；
- 重跑 ✅ 就绪：`configs/wcm_reg4_early_exp_s3072.yaml`（除 register_insert 外与 wcm_reg4_exp_s3072 逐项一致，单变量）+ 一键脚本 `17_train_reg4_early.sh`（训练→5cut→OOD）；两个评估脚本已挂 `reg4_early_exp_s3072` 条目；
- 判读锚点：baseline_exp_s3072（5cut 0.04061 / OOD +0.141）、reg4_exp_s3072-late（0.04068 / +0.103）——early 版若显著优于两者 → D2 线复活、combo 重议；仍无差异 → "寄存无增益"坐实。

**对历史数据的影响标注**：§4/§5/§6/§8.1/§8.2 中所有 reg4/D2 结果（旧数据 + 扩训）均为"late-双倍深度变体"，修复重跑前应视作"深度混淆的参考值"；baseline/bs1/noleak/treg4 等其余线不受影响。另注意：早期"帧号计数"诊断（15_diagnose_frame_counting.sh）跑的 reg4_d2 也属此列，其分桶结论不受影响（那是按位置的统计，与深度无关）。
